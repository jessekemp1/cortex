2. CODE QUALITY

Grading: Prototype-Grade with Production Aspirations

WARN 5,270 print() calls vs 659 logger calls. The codebase overwhelmingly uses print() for output. This is fine for a personal CLI tool but disqualifying for production. No structured logging means no log levels, no filtering, no rotation, no observability.
WARN 249 except ImportError blocks. The entire import system is held together with conditional imports and sys.path.insert hacks (147 of them). This is because the project isn't properly packaged — it relies on directory-relative imports that break depending on how you run it. 4. SHIPPING BLOCKERS

BLOCKER Requires Python 3.11+ but doesn't enforce it at install time. pyproject.toml says requires-python = ">=3.11" but the cortex entry script has a fallback for Python 3.9 site-packages: site_packages = Path.home() / "Library/Python/3.9/lib/python/site-packages". A user on 3.10 will get cryptic import errors.
BLOCKER Hardcoded paths to /Users/jesse.kemp/Dev. Found in: self_audit.py (REPO_ROOT), engines/conversation_ingestor.py, scripts/gen_demo_cast.py, scripts/gen_demo_pdf.py. self_audit.py will crash on any other machine.
BLOCKER Package structure breaks imports. The project uses both from cortex.X import Y and from X import Y patterns, with 147 sys.path.insert hacks to make either work. A beta user running pip install -e . will hit import failures because setuptools.packages.find excludes many directories that are still imported by the code that IS included.
BLOCKER cortex init is required but under-documented. The install guide mentions it but doesn't explain what it creates. If the ~/.cortex/ directory structure isn't right, most commands fail silently or with unhelpful errors.
BLOCKER Bridge server must be running for MCP/intelligence features. The MCP server calls http://127.0.0.1:8765 via the bridge API. There's no clear documentation on how to start and keep the bridge running. The com.cortex.runtime.plist (macOS launchd) exists but is macOS-only.
WARN .env.template contains sk-ant-api03-YOUR_KEY_HERE. Not a real key, but the prefix format could trigger secret scanners. Use a clearly fake placeholder.

BOTTOM LINE

Cortex has a real product in it. The intelligence layer, conductor, MCP integration, and briefing system are genuinely useful. The problem isn't code quality in the core — it's that the core is buried under layers of experiments, abandoned versions, and speculative features that were never pruned.

The pattern is clear from the commit history: 40 commits on March 8 alone, 353 total across ~3 months. Features are being added faster than dead code is being removed. The ROADMAP.md is 34K characters. The DESIGN_PRINCIPLES.md exists. The ICLR pitch exists. The marketing site exists. What doesn't exist is a clean install path for someone who isn't you.

The fix is deletion, not addition. Delete 30% of the repo, fix the package structure, remove the hardcoded paths, and ship. The intelligence layer is ready. The packaging around it is not. Three focused days gets you to beta. Don't let perfect be the enemy of shipped.
